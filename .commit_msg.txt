fix(astrovox): make the autograd engine correct for deep networks

Gradients now reach every layer of an arbitrarily deep stack. Previously a
gradient that stopped partway through still let the loss fall, so the only
symptom was that early layers never trained. Six independent defects each
silently truncated the graph.

Engine
  - A backward returning a bare tensor instead of a tuple made the engine
    iterate that tensor's rows and treat each as a separate input gradient.
    Every single-input activation had this. The engine now normalises the
    result, and Function.backward documents the tuple contract.
  - Gradients were aligned to the parent's output shape rather than the
    parent's input at that slot, and the slot index was taken from the current
    node, so a gradient landed on the wrong operand.
  - View inverses reinterpreted memory layout, but gradients arrive in logical
    order. Transposing a gradient through a strided view scrambled it; all view
    inverses now work on logical axes.
  - A strided reshape copied into a detached tensor, cutting the graph. The
    copy now goes through Materialize, whose backward is the identity. This
    sits on the attention hot path, where heads are permuted then reshaped.
  - Slice and narrow never recorded a node at all, so their gradients stopped
    at the slice. SliceSpec now scatters into the source shape, using
    length-1 windows for integer indices.
  - matmul used len() on a NumPy array, which is the first axis rather than
    the rank, so batched gradients were mis-padded. The batch dimension is now
    reduced out of a shared weight, and the vector cases use einsum, because a
    vector contracts against a different axis than a matrix does.

Operators
  - LayerNorm and RMSNorm gave the scale the same gradient as the shift. The
    scale is applied before the shift, so its derivative is weighted by the
    normalized activations; only the shift's is the plain sum.
  - Exp.forward called the public exp() helper, re-entering itself forever.
  - Mul with a Python scalar called .numpy() on the float.
  - clip_grad_norm rebound an attribute on the gradient object rather than the
    owning parameter, so it silently did nothing. It now scales in place.
  - MaskedSoftmax and the grouped-query head repeat were raw NumPy and severed
    the graph; both are Functions now. The embedding was likewise a detached
    gather, so a token table never trained.

Framework
  - Registered buffers were not attribute-accessible, so PositionalEncoding
    could not read its own table. Module.__getattr__ now exposes buffers.
  - state_dict returned live references, so a later optimizer step rewrote a
    caller's snapshot. It returns copies.
  - _raw_reshape is usable from inside a backward pass on a strided gradient.

Verification
  - astrovox/tests/test_autograd_graphs.py: 39 tests over hand-built graphs of
    two to five operations, each checked against a closed-form derivative:
    single-op graphs, broadcast reduction, multi-parent accumulation,
    reduction over leading and trailing axes, batched matmul against an exact
    directional derivative, and view routing for every view kind.
  - astrovox/tests/test_training.py: 38 tests asserting that depths 2 through
    16 all deliver nonzero gradients to every layer, that the gradient check
    passes across architectures, that four optimizers converge, and that
    checkpoint and resume reproduce the loss curve exactly.
  - A 10-layer MLP now trains from loss 0.694 to 0.000.
  - A numerical check on a ReLU stack is only meaningful away from the kink,
    so the smooth activation is checked across depths and ReLU is checked with
    inputs held clear of zero; the note records why.
  - The attention key bias has an exactly zero gradient because softmax is
    invariant to a per-row shift. That is encoded as a test so it is not
    later mistaken for a bug.

Also fixes, all found by running the suite without fail-fast
  - The suite was configured to stop at the first failure, hiding six real
    failures behind one.
  - The poisoning defense counted duplicates by sample id, so identical text
    under two ids was missed, which is the actual attack.
  - Watermark detection took a square root of a negative binomial variance
    whenever the green list exceeded the alphabet.
  - API anomaly limits were exclusive, so a client sitting exactly on the
    token limit was not flagged; both limits are now configurable.
  - The abuse blocker hardcoded its five-violation threshold; it is
    configurable.
  - The jailbreak detector had no pattern for the two most common phrasings,
    "ignore all previous instructions" and "act as an unrestricted AI".
  - POST /cost/recommend declared bare parameters, so FastAPI read them from
    the query string and rejected the JSON body with 422.
  - The metric endpoints shared one module-level store, so two applications
    mounted with the router saw each other's samples and queries were
    non-deterministic. Each app now owns its store.
  - Missing WatermarkConfig and QueryRecord imports in the security tests.
  - astrovox/tests is a package, so test_training.py no longer collides with
    the repository's top-level tests/test_training.py.

741 passed, 17 skipped.
