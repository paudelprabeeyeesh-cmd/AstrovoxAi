docs(astrovox): document the framework and add a runnable example

Six documents covering what the package is, how each part works, and what is
not there yet. The limitations section is deliberate: an empty list of known
gaps is more useful than none.

astrovox/README.md
  Status table, quick start, the four-call training loop, layout, and links.
  Notes that the core has no PyTorch dependency, and says plainly what is
  missing: no accelerator backend, no distributed execution, no compiler or
  fusion, quadratic attention memory, and NumPy-bound performance.

astrovox/docs/tensor.md
  Storage, stride, and why a strided view is materialized with as_strided over
  a flattened alias. The three details that each cost a bug: flattening the
  storage first, taking rank from .ndim rather than len, and the bounds check
  that exempts empty views. The view-gradient table, why a strided reshape
  needs the Materialize node, the broadcast and reduction inverses, dtype
  promotion, and the serialization format with the reason it stores raw bytes
  rather than pickle.

astrovox/docs/autograd.md
  The Function protocol, the implicit graph, and the backward contract with
  the bare-tensor case spelled out. Ordering by sequence number, accumulation,
  and why the gradient at position i belongs to node.inputs[i] rather than to
  the parent's input list. The broadcast and reduction inverses, batched matmul
  with einsum for vector operands, and why views are graph nodes. Three
  verification strategies and the two situations that need explicit handling:
  a non-smooth function at a kink, and a gradient that is legitimately zero.

astrovox/docs/debugging.md
  The tool for each failure mode, with the order to try them. Emphasises
  calling check_graph before backward, since a backward releases the graph.

astrovox/docs/execution.md
  What executes an operation today, FLOP accounting conventions, timing,
  roofline ratios, and the memory figure that matters for training. Records
  what measurement actually showed: a single wide Linear takes about 0.5 ms
  while the full two-layer forward takes about 9 ms, so the cost is graph
  construction and view materialization rather than BLAS. Then the next five
  optimizations in value order, starting with keeping weights in both layouts.

astrovox/examples/train_transformer.py
  A runnable module, python -m astrovox.examples.train_transformer, that
  trains a small language model and then runs the diagnostics over it. It uses
  only the public API, so it also serves as a check that the documented entry
  points exist. All 31 transformer parameters pass the gradient check.

Two fixes found by writing the example
  - LanguageModel yielded the head's parameters both as a registered submodule
    and explicitly, so every head weight appeared twice and the optimizer
    applied each update to it twice.
  - The reported figure in gradient_consistency was named as a norm-relative
    error but was actually the largest element error over the gradient norm.
    Renamed to match what it measures.
