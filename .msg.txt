feat(astrovox): profiler, FLOP accounting, and a working language model

Closes out the remaining priorities: measure the engine, then use it to train
a real model end to end.

astrovox.profile
  count_flops() counts a forward pass from the recorded graph, splitting the
  total by operation. Matmul flops are checked against the analytic value
  (2 * m * k * n, scaled by batch), and views count as zero because they move
  no data. count_backward_flops() doubles a forward cost, which is right for
  most differentiable ops and correctly zero for views and embeddings.
  Profiler times named regions and reports throughput. AllocationTracker
  counts buffers, bytes, and distinct shapes. Roofline helpers give bandwidth,
  cache residency, and arithmetic intensity, which is what decides whether a
  kernel wants better math or fewer accesses.

astrovox.nlp
  CharTokenizer is byte-level over all 256 values, so any input is encodable;
  it previously covered only printable ASCII, which silently replaced tabs and
  newlines. WordTokenizer fits a frequency cutoff. Dataset slices a corpus into
  windows whose target is the input shifted by one.
  batches() cycles infinitely for training and epoch() returns a finite pass
  for validation. The distinction matters: validating by materialising a
  repeating generator exhausts memory.

  LanguageModel is a causal transformer with a tied-free linear head, gradient
  clipping, linear warmup, and cosine decay. The learning rate is derived from
  the step counter rather than a separate scheduler object, because two counters
  that must agree are two things to restore and one thing to forget.
  sample() generates with temperature and top-k, under no_grad.

  Trained on a synthetic corpus, validation loss falls 2.77 to 2.61 and
  perplexity 15.9 to 10.4 over 100 steps of an 87k-parameter model.

Three resume bugs, each silent
  Optimizer state was keyed by id(param). An id is only meaningful inside one
  process, so a reloaded checkpoint's state was never found and the optimizer
  silently restarted with fresh moments. State is keyed by position in the
  parameter list instead.
  Optimizer state travels through the JSON manifest as keys, which come back
  as text. Left as strings, every lookup missed. They are converted back to
  integers on load.
  The step counter and optimizer state were written but not read back, so a
  resumed run restarted its warmup and learning rate from zero.

Also found by writing the tests
  - Tensor.backward() did not exist; loss.backward() is the expected spelling.
  - CharTokenizer.load passed a vocab argument the constructor does not accept,
    so loading a saved tokenizer raised.
  - decode() dropped multi-character special tokens even when asked to keep
    them, so an id sequence with BOS and EOS decoded to the same string either
    way.
  - The checkpoint format could not hold a second module's tensors, which a
    language model needs for its head. save_checkpoint now takes namespaced
    groups.
  - @no_grad() could not be used as a decorator; it is a context manager
    whose instance is not callable.
  - LanguageModel exposed no state_dict or named_parameters, so it could not
    be checkpointed or inspected as a model.

astrovox/tests/test_profiler.py (27 tests) checks flop counts against analytic
values for matrices, batches, and vectors, and asserts a view costs nothing.

astrovox/tests/test_language_model.py (38 tests) covers tokenizer round trips
including control characters and unknown words, the shift-by-one dataset
contract, training reducing loss and perplexity, every parameter receiving a
gradient, a checkpoint reproducing predictions exactly, and resume continuing
the same trajectory rather than restarting.
