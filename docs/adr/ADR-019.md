# ADR-019: Benchmark-Gated Performance Policy

## Status
Accepted

## Context
Performance regressions must be caught before merge, and microbenchmarks must be statistically sound to avoid flaky gates.

## Decision
`internal/benchmark` provides a statistical harness: repeated trials, IQR-based outlier removal, p50/p95/p99 reporting, and regression gating against stored baselines. Every optimization PR runs the harness; gates fail the build on regression beyond tolerance.

## Consequences
- Benchmarks are part of CI, not optional.
- Outlier removal prevents noisy CI machines from false failures.
- Baselines are versioned with the source.
