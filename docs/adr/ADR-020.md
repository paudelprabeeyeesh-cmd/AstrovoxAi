# ADR-020: Observability-First Design

## Status
Accepted

## Context
Production engines need metrics, traces, and health signals from day one; retrofitting observability is costly and inconsistent.

## Decision
Every engine package emits structured metrics through `internal/profiler` (hierarchical spans, time-series sampling) and exposes health/diagnostics hooks. The runtime package aggregates per-session metrics; the CLI surfaces them via `astrovox doctor` and `astrovox profile`.

## Consequences
- Metrics are a first-class API concern, not an afterthought.
- Spans are hierarchical, enabling end-to-end latency attribution.
- Diagnostics are reachable from the CLI without code changes.
