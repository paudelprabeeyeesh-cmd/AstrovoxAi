# ADR-014: TIR and the Compiler Lowering Pipeline

## Status
Accepted

## Context
Executing graph-defined computations efficiently requires an intermediate representation that can be optimized and lowered to kernel calls.

## Decision
`compiler` defines TIR (Tensor IR) with explicit ops, shapes, and layouts. The pipeline is: graph -> TIR -> TIR optimizations (`tir_opt.go`) -> lowering to kernel dispatch (`lowering.go`) -> backend emission (`backend.go`). `internal/ir` holds the CFG/dominator analysis used by TIR passes.

## Consequences
- Optimizations (fusion, CSE) are reusable across backends.
- Shape propagation lives in the IR, catching shape errors at compile time.
- Dominator analysis enables control-flow-aware passes.
